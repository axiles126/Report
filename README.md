# Reports (Копібара) — PWA · версія 2026.10.06

Одностраничное офлайн-приложение для FPV/БпЛА расчётов: таймер вылетов,
шаблоны, отчёты (Зараз / День / Ніч / Доба / 7 днів), редактор смены,
карта Leaflet с точками MGRS, погода, голосовое управление.

## Состав

| Файл | Назначение |
|---|---|
| `index.html` | всё приложение: MGRS-конвертер, UI, логика, стили |
| `sw.js` | service worker, управляемое обновление (VERSION + NOTES) |
| `manifest.webmanifest` | манифест PWA |
| `leaflet.js`, `leaflet.css` | карта (локальные копии) |
| `icon-192.png`, `icon-512.png` | иконки приложения |

## Развёртывание

Положить все файлы в один каталог на HTTPS-хостинге (GitHub Pages подходит).
Пути относительные, подкаталоги не нужны.

При каждом обновлении поднимать `VERSION` в `sw.js` и добавлять строку
в начало `NOTES` — иначе установленные устройства продолжат работать
со старой копией из кэша. Пользователь увидит окно «Доступне оновлення»
со списком изменений и обновится по кнопке.

## Что изменено в этой версии

1. **Живое обновление редактора.** `syncEditor()` перерисовывает открытый
   редактор при новом взлёте, посадке, добавлении шаблона, координатах
   с карты, сбросе смены и восстановлении из IndexedDB. Перерисовка
   пропускается, если данные не изменились (сравнение сигнатуры), и
   откладывается до выхода из поля, если пользователь печатает.

2. **Отчёт «Зараз».** Число вылета в одной строке с СП:
   `СП Капібара 29.07.26`.

3. **«Доба» и «День/Ніч».** Первая строка — `Екіпаж СП "<назва>":`,
   вторая — дата/диапазон.

4. **Новый шаблон День/Ніч** (пункты 1–9 фиксированы, свои шаблоны
   и кастомные поля идут после них номерами 10+):

   ```
   Екіпаж СП "Капібара":
   18:00-06:00 28.07.2026-29.07.2026
   1. Кількість розвідувальних вильотів - 10
   2. Кількість виявлених цілей противника - 1
   3. Кількість проведених коригувань засобів ураження - 8
   4. Супровід СОУ - 0
   5. Супровід НРК - 0
   6. Втрати БпЛА - 0
   7. Пошкодження БпЛА - 0
   8. Витрачено пропелерів - "Тип А" 0 шт,"Тип Б" 0 шт
   9. Дронів на позиції 4Т - 1 шт
   ```

   «Ніч», открытая утром (когда ночная смена ещё не началась), показывает
   прошедшую ночь, а не пустую предстоящую.

5. **Координаты к конкретному шаблону.** На карте «У звіт» открывает список
   шаблонов текущего вылета; координаты подставляются к выбранной строке
   (`Корегування артилерії за координатами 36UVV6846641264`). Строки, где
   координаты уже есть, подсвечены — повторный выбор заменяет их.
   Кнопка «До вильоту» — прежнее поведение (координаты на весь вылет).
   Дублирование в «Добе» и «Зараз» устранено.

6. **Погода на главном экране.** Строка под таймером, подтягивается
   автоматически по текущему GPS, без тапов. Кэшируется в
   `kap_wxcache` (+ IndexedDB), поэтому показывается мгновенно и офлайн;
   старше часа — с пометкой времени. Обновление при запуске, возврате
   в приложение и раз в 15 минут; сеть не дёргается, если данные свежее
   15 минут и позиция не сдвинулась больше ~5 км. Тап — принудительное
   обновление. Строка всегда укладывается в одну строку экрана: температура,
   ветер и осадки фиксированы, описание погоды сжимается с многоточием;
   полные данные (порывы, влажность, «ощущается», время замера) — в подсказке
   по долгому нажатию.

7. **Чекбокс «Показувати час у польоті» по умолчанию выключен.** Строка
   `У польоті: MM:SS` в отчёте «Зараз» появляется только если включить его
   вручную; выбор сохраняется.

## Известные проблемы (не исправлено)

1. **`sw.js` → `ASSETS` содержит `./images/layers.png`, `marker-icon.png`,
   `marker-icon-2x.png`, `marker-shadow.png`, `layers-2x.png`.** Если этих
   файлов нет на сервере, `cache.addAll()` падает целиком и офлайн-режим
   не работает вообще. Приложение рисует только `L.circleMarker`, дефолтные
   иконки Leaflet ему не нужны. Варианты: убрать эти пути из `ASSETS` либо
   кэшировать поштучно:

   ```js
   e.waitUntil(caches.open(CACHE).then(c =>
     Promise.allSettled(ASSETS.map(a => c.add(a)))));
   ```

2. **Тайлы карты не кэшируются** — офлайн карта пустая. Нужен runtime-кэш
   тайлов в SW с ограничением объёма или предзагрузка района.

3. **OPSEC.** Текущие координаты уходят на `api.open-meteo.com` при каждом
   запуске автоматически; тайлы раскрывают просматриваемый район. При
   необходимости — округлять координаты перед запросом погоды.

4. **Мелочи.** `kap_daystart` и `kap_showair` пишутся в IndexedDB, но не
   читаются оттуда; поле «Позивний старшого групи» сохраняется, но в текст
   отчёта нигде не попадает; в manifest одна иконка с
   `purpose: "any maskable"` — щит на белом фоне при maskable-обрезке
   потеряет края.
